# Release v2.2.0 — Secure Parameterized Queries & Advanced GroupBy Features

## Overview

This release brings crucial security enhancements and flexible features to `@mlagie/sql-connector` without introducing any breaking changes. The library now natively uses **Prepared Statements** under the hood. Your queries are automatically protected against SQL Injection vulnerabilities while your existing code remains 100% retrocompatible.

## What's New for Users

### 1. Transparent SQL Injection Protection

When using core methods like `.find()`, `.save()`, or `.count()`, data parameters are now automatically isolated and compiled using SQL placeholders (`?`).

- **Benefit**: You don't have to change anything in your current code. Your applications are now protected against SQL injection attacks by default.

### 2. Multi-Type `groupBy` Configurations

The `.find()` method's `groupBy` option has been upgraded. You can now pass an array mixing raw column names, custom identifiers (`col`), and time-series conversions (`dateFormat`) in a single query:

```js
// You can now mix strings and advanced objects natively
const records = await MyModel.find({
  select: [
    { col: 'role', as: 'user_role' },
    { dateFormat: ['createdAt', '%Y-%m'], as: 'period' }
  ],
  groupBy: [
    'status', 
    { col: 'role', as: 'user_role' },       // Safely resolves to your alias: `user_role`
    { dateFormat: ['createdAt', '%Y-%m'] }   // Generates: DATE_FORMAT(`createdAt`, '%Y-%m')
  ]
});
```

### 3. Smart Alias Resolution in Groupings

If you specify an `as` alias property inside a `groupBy` object (like `{ col: 'role', as: 'user_role' }`), the ORM automatically routes the group evaluation using that direct alias. This guarantees valid SQL generation and prevents common MySQL syntax errors.

## Full Changelog

### Core Models & Filters

- **Feature**: Added support for `col` and `dateFormat` structured objects inside the `groupBy` array of `.find()`.
- **Feature**: Added automatic native query routing via the `as` alias property within groupBy configurations.
- **Security**: Added strict empty array checkers on logical `OR` and `AND` filters. Passing an empty array (`OR: []` / `AND: []`) will now raise a clear semantic error (`OR conditions cannot be empty`) to prevent unintended wide-open database queries.

### Quality Assurance & StabilityCode

- **Coverage**: Hardened the global testing architecture, successfully establishing a strict **minimum threshold of 90% production code coverage**. Unreachable edge-cases and defensive SQL connection recovery boundaries have been isolated to ensure optimal suite velocity and stability.
