# Release v3.0.0 — The Multi-Dialect Update 🚀

## Overview

Version 3.0.0 introduces native PostgreSQL support and a new SQL dialect architecture. The connector can now target MySQL or PostgreSQL while keeping MySQL as the default database engine.

## What's New

### 1. Native PostgreSQL Support

PostgreSQL connections are now supported through the `pg` driver:

```js
const { connect } = require('@mlagie/sql-connector');

await connect({
    host: 'localhost',
    port: 5432,
    user: 'postgres',
    password: 'password',
    database: 'mydatabase'
}, 'postgres');
```

MySQL remains the default:

```js
await connect(config);
```

### 2. SQL Dialects

SQL generation is now delegated to the active dialect. Each database engine provides its own implementation for:

- identifier escaping;
- value escaping;
- parameter placeholders;
- UUID generation and extraction;
- affected-row counting;
- default value formatting;
- database-specific table options.

MySQL uses backticks and `?` placeholders, while PostgreSQL uses double quotes and numbered placeholders such as `$1`, `$2`, and `$3`.

### 3. PostgreSQL-Compatible Defaults

Column defaults are now formatted according to the selected database:

- PostgreSQL strings use single-quoted SQL literals;
- PostgreSQL booleans use `TRUE` and `FALSE`;
- MySQL keeps its native formatting;
- dates, objects, numeric values, temporal SQL defaults, and function defaults are supported by both dialects.

### 4. Foreign Key Synchronization

Table synchronization now handles dependencies between tables and generates foreign key constraints from schema declarations, including tables with multiple foreign keys:

```js
const orderSchema = new Schema({
    user_id: { type: Number, foreignKey: 'users(id)' },
    product_id: { type: Number, foreignKey: 'products(id)' }
});
```

Dependencies are created in the correct order, and cyclic dependencies are detected with a descriptive error.

## Breaking Changes

- `connect()` now accepts an optional second argument: `dialect`.
- The supported dialect names are `mysql` and `postgres`.
- SQL identifier and value escaping is handled by the active dialect instead of a single global implementation.
- Driver results are normalized internally so model operations work consistently across MySQL and PostgreSQL.

## Optimizations and Reliability

- Centralized database-specific SQL behavior in the dialect layer.
- Consistent handling of query placeholders and driver result formats.
- Improved UUID generation for both supported databases.
- More robust CRUD operations and affected-row handling.
- Expanded multi-dialect test coverage for models, queries, defaults, joins, foreign keys, and connection handling.

## Upgrade

```sh
npm install @mlagie/sql-connector@latest
```
