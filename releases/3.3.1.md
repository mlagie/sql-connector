# v3.3.1

## Fixed

- **Migration rollback files are now written before the schema is modified.**
  Previously, `<id>.sql.enc` and `<id>.meta.json.enc` were written after the
  transaction was committed. If the process failed or was interrupted in between,
  the database recorded the migration as applied while the files required for
  `rollback` were missing. They are now written first, so a failed write stops the
  migration before anything is changed.
- **Failed migrations no longer leave files behind.** If the transaction fails
  and is rolled back, the migration files written for it are removed
  (new `MigrationStore.removeMigration(id)`).
- **Post-commit steps no longer report a committed migration as failed.** If
  writing the schema snapshot or running `cleanup()` fails after the commit, the
  migration is still reported as applied. The problem is logged and returned in
  `result.warnings`.

## Notes

- No API changes. The order of operations inside a migration is unchanged from 3.3.0
  (deletions first, then additions and alterations).
