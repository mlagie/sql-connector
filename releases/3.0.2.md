# Release 3.0.2 Dialect-dependent SQL placeholders

## Fixed

- **Dialect-dependent SQL placeholders**: `buildQueryParts` was generating literal `?` in `WHERE` and `LIMIT` clauses, which broke queries in Postgres (which expects positional placeholders like `$1`, `$2`, ...). Fixed by replacing them with `getDialect().getPlaceholder(index)`, including correct index tracking for `IN` / `NOT IN` clauses containing multiple values.
- **NULL comparisons**: A `WHERE column = NULL` condition (automatically generated when a `null` value was provided in `where`) never returned any results, as `NULL` is never equal to anything in SQL. `buildWhere` now generates `IS NULL` / `IS NOT NULL` when the value (or `{ "=": null }` / `{ "!=": null }`) is `null`, without consuming a placeholder index.

## Impact

- Any query filtering on a null column (`{ parent_uuid: null }`) now works correctly again on both MySQL and Postgres.
- Postgres queries using `IN`, comparison operators, or `LIMIT` now receive valid `$n` placeholders generated directly by `buildQueryParts`, instead of relying on post-hoc regex replacement in `dialects.js`.

## Migration Notes

No API changes. Query results filtering on `null` may change, as rows that were previously unfound will now be returned correctly.
