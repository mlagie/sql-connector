# v3.4.0

## Added

- Added explicit database table renames through model `oldname` metadata.
- Added safe rename SQL generation for MySQL and PostgreSQL, with migration planning, collision detection, backups and rollback support.

## Fixed

- PostgreSQL schema inspection now detects `IDENTITY` columns, primary keys and unique constraints. This prevents existing identity columns from being reported as unrelated schema changes.
- PostgreSQL schema comparison now treats JavaScript `Number` and PostgreSQL `int4` as equivalent integer types, and recognizes identity declarations expressed with `GENERATED BY DEFAULT AS IDENTITY` or `GENERATED ALWAYS AS IDENTITY`.
- PostgreSQL column alterations no longer emit `DROP DEFAULT` or `SET DEFAULT` for identity columns, avoiding an invalid operation rejected by PostgreSQL.
- PostgreSQL JSON/JSONB object defaults are serialized as valid JSON instead of JavaScript's `[object Object]`; JSONB defaults are normalized during inspection to avoid repeated no-op alterations.
- Migration and backup identifiers are validated before they are used to build filesystem paths, blocking path traversal through caller-supplied identifiers.

## Tests

- Added regression coverage for PostgreSQL identity introspection, schema equivalence and safe migration-store identifiers.
- Added coverage for rename planning, absent and conflicting table names, dialect SQL, and rollback operation generation.
