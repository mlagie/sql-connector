## v3.3.0

### Added
- **`MAX` aggregation in `select`** for both the SQL (MySQL) and PostgreSQL dialects.
  Use the `max` key in a select item, optionally with an alias:

```js
  select: [{ max: "created_at", as: "latest" }]
```

  `max` accepts the same value shapes as `count` (a column name, a list of columns,
  or an object condition). TypeScript typings were added to `SelectAggregation`.

### Improved
- **Migration plan ordering:** column deletions (`dropColumn`) are now planned
  **before** column additions and alterations. This fixes the
  `multiple primary keys for table` error when a primary key column is replaced
  (for example, dropping `uuid` and adding `id` as the new primary key).
  Renames are still applied first, and rollbacks follow the reversed order.

### Notes
- This is a backward-compatible release. Migration plans generated with an earlier
  version may list their operations in a different order, so regenerate them with
  `plan` before applying.
