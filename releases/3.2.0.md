# Release 3.2.0

## PostgreSQL support

- Added PostgreSQL as a supported database dialect alongside MySQL.
- Added PostgreSQL-specific SQL generation for identifiers, placeholders, data types, defaults, date formatting, case-insensitive comparisons, UUID generation and affected-row counts.
- Added PostgreSQL-compatible execution through the `pg` client.
- Added PostgreSQL schema inspection and migration compatibility.

## Dialect-aware models and queries

- Model creation and inserts now use the active dialect for SQL types, auto-increment columns, quoting and parameter placeholders.
- Date formatting in `SELECT` and `GROUP BY` clauses now uses the appropriate function for each database engine.
- Case-insensitive `LIKE` conditions now use the native implementation of the active dialect.
- Added validation for SQL identifiers before dialect-specific escaping.

## Compatibility

- MySQL remains supported with its existing SQL syntax and behavior.
- The package version and lockfile are now set to `3.2.0`.

## Migration notes

No breaking API changes are intended. Select the database engine with the existing dialect configuration before connecting or running queries.
