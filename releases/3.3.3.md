# v3.3.3

## Changed

- **`instance.delete()` without arguments now targets the row by its primary key only.**
  Previously, every value of the loaded record was used as a `WHERE` condition
  (`DELETE ... WHERE id = ? AND email = ? AND ...`). The condition is now built from
  the column(s) declared with `primary_key: true` in the schema
  (`DELETE ... WHERE id = ?`), matching how `updateOne()` already identifies a row.
  Composite primary keys are supported.

## Safety

- If the record does not contain **all** the primary key columns, `delete()` falls
  back to the whole record instead of using a partial key that could match several rows.
- If the schema defines no primary key, the whole record is used, as before.
- If the current row cannot be identified (empty, `null`, or non-object data),
  `delete()` now throws `Cannot delete: no primary key or record data available to
  identify the row.` instead of sending a `DELETE` without a `WHERE` clause.

## Documentation

- Updated the `instance.delete()` entry in `docs/API.md` and the parameterless
  `delete()` JSDoc in `index.d.ts`.

## Tests

- Added tests for primary-key-only deletion, composite keys, schemas without a
  primary key, partial keys, JSON-string records and unidentifiable rows.

## Notes

- `instance.delete(filter)` with an explicit argument is unchanged.
- Behavior change: because only the primary key is matched, `delete()` now also
  removes the row when its non-key columns were modified in the database after the
  instance was loaded. Previously such a row was not matched and `delete()` returned `0`.
